# CSP-S 复赛算法思维训练法

> 从“学过某个算法”转向“面对陌生题能自己推出可行解”。
> 本文只讨论通用方法，不记录个人成绩、目标分数与训练日程。

## 一、核心判断

CSP-S 复赛真正拉开的差距，通常不是“谁多背了一个数据结构”，而是下面三件事：

1. **题面 → 模型**：能把自然语言翻译成可操作的状态、转移、约束。
2. **暴力 → 优化**：先写出一定正确的朴素解，再从瓶颈里找到关键性质。
3. **看懂 → 写对**：关掉题解仍能独立实现，并能用反例和对拍证明它没错。

因此，训练的最小单位不该是“今天学单调栈”，而应该是一道题的完整链条：

```text
一道题 → 一种直觉 → 一个暴力解 → 找出瓶颈
      → 一个关键观察 → 更优算法 → 独立实现 → 对拍验证 → 迁移到新题
```

算法名称是这条链的**结果**，不是起点。只记名称，遇到变形题仍然不会；走过一遍链条，才有可能在考场上复现同样的思考。

## 二、六步闭环

每道值得做的题，都按下面六步走。每一步都要有可见产出，不能只停留在“看懂了”。

| 步骤 | 要做什么 | 产出 | 过关标准 |
| --- | --- | --- | --- |
| 1. 建模 | 用 5～10 个元素手算；分开写输入、限制、目标、边界 | 一句话模型 + 一个手算例子 | 能不看题面复述“要求什么” |
| 2. 最简正确解 | 枚举、DFS、朴素 DP 均可；先不追求快 | 可运行代码 + 正确性理由 | 过样例，且能解释为什么对 |
| 3. 找瓶颈 | 数状态数、转移数、重复扫描次数 | 复杂度表达式 + 最慢的一步 | 能指出“减少哪一部分工作” |
| 4. 关键观察 | 找不变量、等价转化、可删状态；同时找反例 | 三句话以内的证明 | 能回答“为什么成立”和“条件变了还成立吗” |
| 5. 独立实现 | 关题解、关代码，自己写 C++ | 编译通过的代码 | 样例、边界、特殊数据都过 |
| 6. 对拍验证 | 最小数据、特殊性质、随机小数据 | 对拍记录 + 差异解释 | 出现差异时能自己定位，而不是让 AI 直接改 |

这六步不是单向流水线。第 4 步证不出来，常常要退回第 2 步换一种暴力；第 6 步发现反例，也可能推翻第 4 步的“关键观察”。**能来回走，才是真的在做题。**

### 第 1 步：把题翻译成自己能操作的模型

不要急着写代码。先手算：

- 输入规模是多少？哪些维度可以枚举，哪些必须压缩？
- 目标是最大、最小、计数，还是判定？
- 限制里有没有“严格”“至少”“恰好”“相邻”这类会改变等号的词？
- 边界是什么？n=1、全部相等、单调、距离刚好等于 d，分别会怎样？

如果手算例子都走不通，说明模型还没建好，此时看题解只会记住结论。

### 第 2 步：先写一个一定正确的解

暴力解不是浪费时间，它有三个作用：

1. 强迫自己把题意落实到具体操作；
2. 作为对拍的“标准答案”；
3. 暴露真正的瓶颈——很多优化方向是从暴力解的结构里长出来的。

部分分代码也要认真写。**能稳定拿到的 30 分，比背下来的 100 分更可靠。**

### 第 3 步：定位瓶颈，而不是猜算法

问自己三个问题：

- 是**状态重复**吗？（同一个子问题被反复计算）
- 是**转移太多**吗？（每个状态枚举了过多候选）
- 是**重复扫描**吗？（区间、左右两侧、同一批元素被反复遍历）

对应的优化方向完全不同：记忆化、数据结构、单调性、前缀和、二分判定。先定位，再选工具。

### 第 4 步：关键观察必须带证明

“看起来只需要最近的两个点”不是证明。至少要写清楚：

- 观察的是什么？（可删的边、可合并的状态、可二分的单调性）
- 为什么可以删/可以换？（用反证或构造）
- 题目条件用在哪？（严格大于、距离限制、k 的范围）
- 条件不成立时，反例是什么？

这一条是算法能力的分水岭。**不能解释“为什么”的结论，换一道题就不会用。**

### 第 5 步：关掉题解，独立写

重点检查：

- 状态定义是否完整？下标含义是否前后一致？
- 处理顺序是否正确？依赖是否已经算好？
- 复杂度是否和实现一致？（代码里有没有隐藏的 `sort`、`map`、重复扫描）
- 数组边界、等号、严格/非严格是否与题意一致？
- 数据类型是否会溢出？递归深度是否可能达到 n？

“看懂代码”和“能独立实现”是两种能力。只有后者能在考场上得分。

### 第 6 步：用反例和对拍完成验证

顺序建议：

1. 最小数据（n=1、n=2、k=1）；
2. 特殊性质（全部相等、严格单调、d=1、d=n）；
3. 随机小数据对拍（至少几百组）；
4. 极限数据看复杂度和溢出。

出现差异时，先缩小到最小反例，再判断是题意、建模、边界还是实现问题。**不要第一反应就是让 AI 改代码**；那样修好的是这一份代码，不是你的能力。

## 三、四类题，分别练什么

以 CSP-S 模考 2 的四道题为例，它们表面上考四个知识点，实际上对应四种可迁移的能力。

| 题目 | 表面考点 | 真正要练的能力 | 训练时先问 |
| --- | --- | --- | --- |
| T1 截取密信 | 贪心、字符串、后缀预处理 | 当前选择 + 剩余可行性 | “现在选最早的，后面一定还有解吗？” |
| T2 谁能下到 100 层 | DFS、记忆化、单调栈、DP | 换观察方向，减少状态转移 | “为什么更远的更高平台可以不管？” |
| T3 站岗 | 二分答案、贪心、双指针、树 | 最优化转判定，再利用结构 | “check(D) 到底在检查什么？” |
| T4 种萝卜 | 状态 DP、前后缀最值 | 找必要状态，避免重复计数 | “一列的贡献真的只依赖相邻几列吗？” |

### T1：练“贪心选择的安全性”

T1 的关键不是“早点选”，而是“早点选之后，后缀仍然能完成”。

训练顺序：

1. 先写枚举/暴力，明确什么是一个合法方案；
2. 再写“能选就选”的贪心，尝试构造反例；
3. 找到反例后，补上后缀可行性判断；
4. 最后独立推导 `suf` 的含义、边界和判断条件。

要能回答：**如果当前不选这个位置，后面是否可能更好？** 如果答不上来，贪心就还没有被证明。

### T2：练“图和状态转移”

T2 的关键是从“向下跳”翻成“向上找接住自己的平台”，再把每个点的出边压到两条。

训练顺序：

1. 先写无记忆化 DFS，理解规则和重复子问题；
2. 加记忆化，得到 `O(nd)`；
3. 再想：能不能不枚举所有落点？
4. 最后用单调栈求左右最近更高平台，按依赖顺序 DP。

要能回答：**为什么只保留最近更高？距离限制会不会破坏这个结论？** 这两个问题在下一节展开。

### T3：练“二分答案的建模”

“最大化最小值”是二分答案的典型信号，但会背模板不等于会建 check。

训练顺序：

1. 写出 `check(D)` 的直白含义：能否选出 k 个点，使任意两点距离至少为 D；
2. 先实现枚举起点 + 贪心，拿到部分分；
3. 再研究指针复用、树结构等加速；
4. 每加一层优化，都问“这一步依赖什么性质”。

要能回答：**为什么 check(D) 有单调性？为什么“选当前能选的最左点”是安全的？** 这两个问题比树结构本身更值得先弄懂。

### T4：练“DP 状态设计”

T4 的关键不是一上来就写完整状态，而是先确认“一个格子的贡献到底依赖哪些列”。

训练顺序：

1. 写多维朴素 DP，确保不重不漏；
2. 观察哪些维度是必要的，哪些可以被前缀/后缀最值替代；
3. 先处理小数据与特殊性质，再逐步压缩状态；
4. 每压缩一次，都用小数据对拍确认没有重复计数。

要能回答：**为什么三列就能决定一列的贡献？哪些情况会被重复计算？** 如果说不清，状态压缩只是背结论。

## 四、T2 深挖：从 DFS 到线性（或近线性）

这一节把“关键观察”拆到可以自己复述的程度。

### 1. 题目规则

有 n 个平台，高度 `h[i]`。从 i 跳到 j 合法，当且仅当：

1. `|i - j| <= d`；
2. `h[i] > h[j]`；
3. i、j 之间的所有平台高度都严格小于 `h[i]`。

可以从任意平台出发，求最多经过多少个平台。

### 2. 为什么可以反向看

正向是“从高往低跳”，每个点可能有很多合法落点。反向以后，变成“从矮平台找能接住它的更高平台”。

定义：

- `L[i]`：i 左边最近的、高度严格大于 `h[i]` 的平台（且距离 ≤ d）；
- `R[i]`：i 右边最近的、高度严格大于 `h[i]` 的平台（且距离 ≤ d）。

结论：

```text
dp[i] = 1 + max(dp[L[i]], dp[R[i]])
```

没有父亲时 `dp[i] = 1`，答案取所有 `dp[i]` 的最大值。

### 3. 为什么只需要最近更高

设 `p < q < i`，p 能直接跳到 i。要证明：p 不需要直接连 i，走 `p → q → i` 不会更差。

- 因为 p 能跳到 i，所以 p、i 之间所有平台都低于 `h[p]`，特别地 `h[q] < h[p]`；
- 因此 `p → q` 满足高度条件；距离上，`q` 在 `p` 和 `i` 之间，`|p-q| <= |p-i| <= d`，也满足；
- 因为 q 是 i 左边**最近**的更高平台，q、i 之间不可能有高于 `h[i]` 的平台，否则那个平台会比 q 更近；所以这些平台都 ≤ `h[i] < h[q]`；
- 因此 `q → i` 也合法。

于是 `p → i` 这条边可以被 `p → q → i` 替代，路径还多一个平台。**更远的更高平台不会带来更优解，最近更高就够了。**

距离限制不会破坏这个结论：`p → i` 的距离不超过 d，那么它的子区间 `p → q`、`q → i` 也都不超过 d。

### 4. 单调栈求 L / R

从左往右扫，维护一个高度严格递减的栈：

- 当前 `h[i]` 到来时，弹出所有高度 `<= h[i]` 的栈顶。它们被 i 挡住了，不可能再成为后面平台的“左边最近更高”；
- 弹完后，栈顶就是左边最近的更高平台；再检查距离是否 ≤ d；
- 把 i 压入栈。

从右往左再做一遍，得到 `R[i]`。每个位置最多进栈、出栈一次，求 L/R 的复杂度是 `O(n)`。

注意等号：题目要求**严格高于**，所以弹出条件是 `<=`，不是 `<`。等高平台既不能当父亲，也会挡住后面的更矮平台。

### 5. DP 的顺序与复杂度

`dp[i]` 依赖更高的平台，所以必须**先算父亲，再算自己**。常见两种写法：

| 写法 | 做法 | 复杂度 | 注意 |
| --- | --- | --- | --- |
| 按高度排序 | 把所有平台按高度从高到低排序，依次填 dp | `O(n log n)` | 好写好讲，排序是瓶颈 |
| 记忆化 DFS / 拓扑 DP | 每个状态只展开一次，沿父亲递归或按拓扑序填 | `O(n)` | 递归深度可达 n，建议显式栈或拓扑排序 |

**不要把“用了单调栈”直接说成“整题 O(n)”**。如果 DP 前按高度 `sort` 了一遍，总复杂度就是 `O(n log n)`。这不是错误做法，n=2×10⁵ 完全够用，但复杂度要如实写。

### 6. 调用次数 ≠ 状态数

无记忆化 DFS 里，同一个平台会被反复调用，所以“调用 1023 次”并不等于“有 1023 个不同状态”。

加记忆化后：

- **不同状态**只有 n 个，每个只展开计算一次；
- 函数仍然可能被调用多次，只是命中缓存后直接返回，不再展开。

所以准确说法是“展开了 10 个状态”，而不是“调用了 10 次”。这个区分能帮你判断优化到底省在哪。

### 7. 自测

关掉页面后，尝试回答：

1. 为什么反向以后，每个点只需要看左右最近的更高平台？
2. 如果 p 能跳过 q 到 i，为什么 p→q→i 一定合法？距离限制用在哪里？
3. 为什么单调栈弹出时用 `<=`？等高平台会怎样？
4. 你的实现复杂度是 `O(n)` 还是 `O(n log n)`？瓶颈在哪一行？
5. 如果 n=2×10⁵ 且高度形成一条长链，递归写法会有什么风险？

## 五、T3 的一个条件陷阱：曼哈顿距离 ≠ 环上弧长

模考 2 的 T3 题解里有一句需要加条件的话：

> 两点的曼哈顿距离恰好等于两段弧长中的较小值。

这句话**一般情况下不成立**。

### 反例

正方形边长 a=10。取左边中点和右边中点：

- 曼哈顿距离：`|0-10| + |5-5| = 10`；
- 沿边界的较短弧长：走上边或下边都是 `5 + 10 + 5 = 20`。

所以 `10 ≠ 20`。

### 正确的关系

设两点在边界上：

- 在同一条边或相邻两条边上：较短边界弧长就是一条单调的 L1 路径，曼哈顿距离 = 较短弧长；
- 在相对两条边上（左/右或上/下）：曼哈顿距离至少为 a，而较短弧长可能更大。以左右两边为例，若纵坐标分别为 y1、y2，则曼哈顿距离为 `a + |y1-y2|`，较短弧长为 `2a - |y1-y2|`。

### 为什么原题的 check(D) 仍然可用

题目中 k ≥ 4。把 k 个点放到长度为 4a 的环上，k 段相邻间隔之和为 4a，必有一段间隔不超过 `4a/k <= a`。这一段对应的两点在同边或相邻边上，曼哈顿距离就等于这段间隔，所以 `D > a` 一定不可行。因此只需考虑 `D <= a`。

当 `D <= a` 时：

- 同边/相邻边：两个距离相等，阈值判断一致；
- 相对边：曼哈顿距离至少为 a ≥ D，环上弧长也至少为 a ≥ D，两边都会通过。

所以“环上相邻距离 ≥ D”与“曼哈顿距离 ≥ D”在**这个题目的条件下**是等价的。它是一个**阈值可行性等价**，不是普遍的距离恒等式。

这正是需要训练的能力：不仅会套结论，还要知道结论成立的条件。把条件写进笔记，比多背一个公式更有用。

## 六、可视化应该怎么用

可视化最有价值的地方，不是把算法“演一遍”，而是逼学生**在揭晓前先预测**。

| 现有做法 | 更有效的做法 | 验收问题 |
| --- | --- | --- |
| 点击后显示合法跳跃 | 先让学生点出所有合法落点，再揭晓 | “为什么这个点不合法？” |
| 演示 DFS 重复计算 | 同时显示调用次数与不同状态数 | “重复发生在哪一层？” |
| 自动播放单调栈 | 每一步暂停，先问“下一个该弹谁” | “为什么栈顶必须被弹掉？” |
| 自动展示 L/R 边 | 先让学生自己画，再对照 | “更远的更高平台为什么不用连？” |
| 自动填 dp 表 | 先填一个值，再揭晓 | “它依赖谁？为什么已经算好？” |
| 随机塔挑战 | 加入等高、d=1、单调高度等反例 | “这组数据会让哪个结论失效？” |
| 七关通关动画 | 增加闭卷讲解、手写代码、对拍任务 | “离开页面后还能写出来吗？” |

一个重要的防伪标准：

> **能点完七关，不等于会写。**
> 完成度至少应分成四个维度：理解规则、解释转化、独立实现、验证正确性。

可视化适合建立直觉，不能替代手写代码和对拍。看完动画后，至少要做一次“关掉页面”的复现。

## 七、训练记录：不要只记 AC 或分数

每道题建议记录五个维度：

| 维度 | 达标条件 |
| --- | --- |
| 读题 | 能自己举例，并说出限制条件 |
| 建模 | 不看题解能写出正确暴力 |
| 推理 | 能解释优化为什么正确，条件是什么 |
| 编码 | 不看代码能独立实现 |
| 验证 | 能生成反例并完成对拍 |

再记录**提示程度**：

- 完全独立；
- 轻提示（只提醒方向）；
- 关键提示（指出核心观察）；
- 看过正解。

这样才分得清“会做”和“看过”。只写“AC”会把这两种状态混在一起。


## 八、常见误区

1. **把“看懂题解”当成“会做”**：合上题解写不出来，就是还没会。
2. **只背算法名**：知道“这题用单调栈”不等于知道“为什么能删到两条边”。
3. **复杂度与实现不符**：代码里有 `sort`、`map`、重复扫描，却声称 `O(n)`。
4. **忽略等号和严格性**：`<` 与 `<=`、`k` 与 `k+1`、边界取不取，都是常见失分点。
5. **递归深度不设防**：n=2×10⁵ 的链状数据可能直接爆栈。
6. **样例通过就交**：样例往往不覆盖等高、d=1、全单调等边界。
7. **只做新题不复盘**：错题不定位到“题意/建模/复杂度/边界/实现/时间分配”，下次还会错。
8. **训练没有产出**：学了 30 分钟，没有代码、没有证明、没有反例，就不算有效训练。

## 九、赛前怎么用这套方法

赛前不适合再铺开大量新算法。更稳的做法是：

1. 选 2～3 道代表性题目，完整走一遍六步闭环；
2. 安排一次整卷限时模拟，考完先冻结原始代码，再复盘；
3. 从失分中只挑**最可挽回的一处**，做针对性修复；
4. 考前 1～2 天只做工具箱、边界、I/O、文件名检查，不再开新坑；
5. 每天留一个可见产出：一段代码、一个不变量、一个反例，或一次对拍记录。

长期来看，这套方法的目标不是“多会几个算法”，而是：

> 面对一道没见过的题，也能先写出有分数的正确算法，再从问题自身找到优化方向。

这比临时多背几个模板更接近 CSP-S 复赛真正考的东西。
