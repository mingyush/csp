## DFS / BFS：把遍历写稳比学更多图论更重要

### 在同一张图上看两种走法

树边为 `1–2,1–3,2–4`，按邻点编号从小到大访问。DFS 遇到 2 就先深入 4，走到底才回头看 3，顺序为 `1,2,4,3`；BFS 先处理距离 1 为一条边的 2、3，再处理 4，顺序为 `1,2,3,4`。

BFS 队列的变化：`[1] → [2,3] → [3,4] → [4] → []`。先进队的先处理，于是从起点一层层扩展。边权都一样时，第一次发现一个点所走边数最少；边权不同时，“边数最少”不保证“长度最短”。

DFS 的递归调用会记住“从哪儿来、回来后接着看谁”；树上每个非根点只有一个父亲，跳过父亲就够。若图有三角形 1–2–3–1，只跳父亲仍会绕圈，因此一般图要 vis。

邻接表下两者都遍历每点、每边常数次，为 O(n+m)。BFS 应在**入队时**标记，避免同一点被多个邻居反复塞进队。

### 树上 DFS

```cpp
void dfs(int u, int fa) {
    for (int v : g[u]) {
        if (v == fa) continue;
        depth[v] = depth[u] + 1;
        dfs(v, u);
    }
}
```

一个 DFS 同时可以顺手算：

- 父节点；
- 深度；
- 子树大小；
- DFN；
- 树 DP 的基础状态。

### BFS

无权图最短步数：

```cpp
queue<int> q;
dist[s] = 0;
q.push(s);

while (!q.empty()) {
    int u = q.front(); q.pop();
    for (int v : g[u]) {
        if (dist[v] != -1) continue;
        dist[v] = dist[u] + 1;
        q.push(v);
    }
}
```

### 当前标准

不是“知道 DFS/BFS”，而是拿到一张小图能自己建图并跑出来。

## 并查集 DSU：连通关系的低代码神器

### 集合代表不是图上的直接邻居

初始 `fa[1]=1,fa[2]=2,fa[3]=3`，每人自成一组。按下方 unite 的写法，合并 1、2 后令 `fa[2]=1`；再合并 2、3，先 find(2)=1，再令 `fa[3]=1`。所以 2、3 同组，虽然未必有直接道路。

find 的问题是“沿代表指针最终找到谁”，不是“返回父亲一次”。路径压缩把途经节点直接挂到最终代表，之后查找更短。实际大规模实现还可按大小/秩合并，避免长链；近似常数的常用复杂度保证通常基于两种优化一起用。

fa 画出来的树是维护集合的辅助结构，不是题目原图：不能沿 fa 求两城市的原始距离。基础 DSU 擅长合并与连通查询，不支持直接删边拆集合。

**理解题**：unite(1,2) 之后又 unite(2,1)，应该新增一个集合吗？不应该，它们的根本来就相同。

### 看到什么想到它

- 两个人是否属于同一组；
- 两个城市是否已经连通；
- 加一条边是否会成环；
- Kruskal。

最小核心：

```cpp
int find(int x) {
    if (fa[x] == x) return x;
    return fa[x] = find(fa[x]);
}

void unite(int a, int b) {
    a = find(a);
    b = find(b);
    if (a != b) fa[b] = a;
}
```

先理解“所有同集合元素最终找到同一个根”，再学路径压缩。

当前对应练习：洛谷 P1551《亲戚》。

## Kruskal：排序 + DSU 就能解决 MST

### 跟着三条边选一遍

三点边为 `(1,2,1),(2,3,2),(1,3,5)`。先选费用 1 的边，集合变 `{1,2},{3}`；再选费用 2 的边，三点全连通；费用 5 的边两端已同组，选了只会成环，跳过。总费用为 3。

每次在当前不同连通块之间选最便宜的边。直觉上，若另一份最优方案没有这条边，加进去会产生一条环；沿环可换掉连接相同两侧、费用不更小的边，方案不会变差。这说明局部选便宜边可以保留某个最优解。

树连通 n 个点恰有 n-1 条边；若扫描完仍不足 n-1 条，输入不连通，不能把局部费用和当全图答案。排序通常占主要时间 O(m log m)。

MST 最小化**整个连通方案的总费用**，不是每个点到某个起点的距离都最短。

### 触发器

题目说：

> 让所有点连通，并让选中边的总费用最小。

第一反应：

```text
边按权从小到大
→ 如果两端已经连通：跳过
→ 否则：选边 + 合并
→ 最终选 n-1 条边
```

核心循环：

```cpp
sort(edges.begin(), edges.end());

long long ans = 0;
int used = 0;

for (auto [w, u, v] : edges) {
    if (find(u) == find(v)) continue;
    unite(u, v);
    ans += w;
    ++used;
}
```

### 容易错

- 只会排序，不会判断成环；
- 忘记检查是否真正选到 `n-1` 条；
- 权值和忘记用 `long long`。

## `priority_queue`：当前最小/最大值不要自己维护

### 堆帮忙挑下一件事，不负责证明策略

普通队列中，先放 7、2、5，先取出 7；最小堆中，先取出 2，再取 5、7。`top()` 只看队顶，`pop()` 删除队顶，没有返回被删的值，所以通常先 top 再 pop。

堆适合“不断加入新候选，每次只需最优一个”。push/pop 通常 O(log n)，top O(1)；它不保证能直接遍历出完整有序序列。

`pair<距离,点号>` 默认先比较 first，再用 second 打破相等。因此 Dijkstra 放 `(dist,u)` 而不是 `(u,dist)`，否则会按点号取点。最大堆/最小堆选反也会改变算法过程。

**理解题**：能一直拿最小值，是否就能解决所有最小化问题？不能；选哪个“最小”以及为什么选它安全，要由算法证明。

最大堆：

```cpp
priority_queue<int> q;
```

最小堆：

```cpp
priority_queue<int, vector<int>, greater<int>> q;
```

最常见用途：

- Dijkstra；
- Prim；
- 每次取当前最小代价；
- 贪心中维护一批“最值得反悔”的选择。

### 重要提醒

`priority_queue` 只是容器，不是算法。要先明确“队顶代表什么”。

## Dijkstra：只在非负边权里用

### 距离是“目前已知最短”，堆里可能有旧消息

有向边 `1→2=2,1→3=7,2→3=1`。起点 1 距离为 0，其余 INF。处理 1 后，堆放 `(2,2),(7,3)`；取出点 2，发现走 1→2→3 只需 3，于是把 dist[3] 改为 3，另放 `(3,3)`。

堆不会自动删掉原来的 `(7,3)`。稍后取出它时，d=7 而 dist[3]=3，说明消息过期，直接跳过。这就是 `if (d != dist[u]) continue` 的作用。

为何非负权重要：当前最小距离点不可能经一个尚未处理、距离更远的点再绕出更便宜的路线；负边会破坏这个理由。不能把“用了堆”当成允许负边的理由。

邻接表加堆的常用实现约 O((n+m) log n)（简单图的常用估算）；重边很多时可按堆规模估 O((n+m) log(n+m))。起点入堆、INF 初始化、过期检查、正确松弛缺一不可。

核心意义：

> `dist[v]` = 从固定起点到 v 的最短路径总长度。

当前只需要掌握：

1. 邻接表；
2. `long long dist[]`；
3. 最小堆；
4. 松弛；
5. 过期状态跳过。

核心片段：

```cpp
while (!pq.empty()) {
    auto [d, u] = pq.top();
    pq.pop();
    if (d != dist[u]) continue;

    for (auto [v, w] : g[u]) {
        if (dist[v] > d + w) {
            dist[v] = d + w;
            pq.push({dist[v], v});
        }
    }
}
```

## DFN：把树拍成数组

### 为什么子树编号不会夹进外人

仍用根 1、边 `1–2,1–3,2–4`，按小编号先走。首次进入编号为 `dfn[1]=1,dfn[2]=2,dfn[4]=3,dfn[3]=4`。DFS 进入 2 后，会把 2 的后代走完才回去，因此 2 的子树恰占编号 `[2,3]`。

若各点权为点号，拍平数组是 `[1,2,4,3]`，求节点 2 子树和就变成区间 `[2,3]` 求和，得到 6。DFS O(n) 后，静态子树和可用前缀和；有修改再接动态结构。

注意 `[2,3]` 是 **DFN 编号区间**，不是原节点编号区间。树上任意两点路径一般也不等于一个 DFN 区间；不能拿子树性质直接套路径。

如果 DFS 只在第一次进入节点时编号，那么：

```text
u 的整棵子树
=
[dfn[u], dfn[u] + size[u] - 1]
```

于是“树上的子树问题”可以转换成“数组的一段区间”。

> **树上不好做 → 能不能拍平以后做？**

## 多源：多个起点一起进队

### 让几股水同时扩散

无权链 `1–2–3–4–5`，起点是 1 和 5。把两点距离同时设为 0 入队：第一层到 2、4，第二层到 3，得到 `[0,1,2,1,0]`，表示到最近一个起点的距离。

逐个起点跑一次再取最小也能做，但重复很多；同时入队只需一次 O(n+m) BFS。非负带权图对应多源 Dijkstra。

它求的是 `min_s dist(s,v)`，不是每个起点到 v 的完整距离表，也不是到所有起点的距离和。

若很多起点到其它点的最近距离：

```cpp
for (int s : starts) {
    dist[s] = 0;
    q.push(s);
}
```

然后只跑一次 BFS / Dijkstra。

理解成“加一个超级源点向所有起点连 0 边”也可以，但代码上通常直接多源初始化更短。

## 反向建图：很多点到同一终点，只跑一次

### 把一条路径完整倒过来

原边 `A→B=2,B→T=3,A→T=10`。原来 A 到 T 最短为 5，B 到 T 为 3。反图边是 `T→B=3,B→A=2,T→A=10`；从 T 跑最短路，仍得到 B 为 3、A 为 5。

每条原路径对应一条反向路径，边权和相同，所以 `原图 dist(u,T)=反图 dist(T,u)`。是**把每条有向边反向**，不能只把算法起点改成 T。反图必须保留原边权。

原问题：

```text
很多起点 → 固定终点 T
```

把所有有向边反过来，再：

```text
从 T → 所有点
```

只跑一次最短路。

这是非常典型的：

> **换方向，减少重复计算。**

## 虚拟节点：把很多特殊情况统一起来

### 多个入口变成一个入口

入口有 A、B；新增 S，连 `S→A=0,S→B=0`，从 S 跑 Dijkstra。到点 x 的距离等于从 A、B 出发的较小距离。路径先免费选入口，之后照原路走，因此与原问题对应。

若从 A 出发还需 5 元，从 B 出发需 2 元，就把两条新边权设成 5、2。新增节点是在表达规则，不能凭方便随意加边。

新节点也占下标，数组必须容纳；有向建模不要自动补反向边。零权新边可用 Dijkstra，但不能当普通无权 BFS 的一步，否则把免费选择入口算成了一步。

例如多个入口可以新增超级源点 0；多种“免费进入方式”也可以通过额外点统一建模。

当前只学思想：

> **如果代码里有很多“如果从 A 开始 / 从 B 开始 / 从 C 开始”，能不能造一个统一入口？**

不要求现在专门刷虚拟节点题。

## 拓扑排序 + DP

### 前置任务做完，才能做后续任务

任务 A、B、C 用时 2、3、4，依赖 `A→C,B→C`；A、B 可以同时开始。C 需等较慢的前置完成，最早完成时间是 `max(2,3)+4=7`，不是 2+3+4。

入度表示还有多少前置未处理；先把入度 0 的点放队列，每处理一条边就减少后继的入度，降到 0 才入队。这样算后继时，其前置值已准备好。

用“以 u 结尾的最早完成时间”作 dp，所有源点初始化为自身用时；不可达状态按题目单独处理。若处理节点数不足 n，说明有环，不可直接把残留 dp 当答案。拓扑遍历 O(n+m)，当前先会解释顺序。

若题目是 DAG（有向无环图），很多“依赖关系上的最优值”可以：

```text
拓扑排序
→ 按顺序 DP
```

核心：

```cpp
for (int u : topo) {
    for (int v : g[u]) {
        dp[v] = max(dp[v], dp[u] + value[v]);
    }
}
```

当前只要求会辨认 DAG，不加入近期必练清单。

## Prim 补充：从一个连通块向外接新点

同样求 MST，Kruskal 是把全图的边排队；Prim 是先选一个点作为当前树，每次挑“当前树到外面”最便宜的边，把一个新点接进来。它比较的是接入的**单条边权**，不是从根走过来的整条路长。

例如无向三角形 1–2 权 4、1–3 权 5、2–3 权 2：从 1 开始，先用 4 接入 2，再用 2 接入 3，树总权为 6。Dijkstra 则发现从 1 到 3 直接走 5 比经 2 的 4+2 更短；这说明两种算法即使都用最小堆，状态含义也不同。

Prim 更新候选点 v 的接入费用时比较 w；Dijkstra 更新距离时比较 dist[u]+w。算法不可只改名字就互换。当前仍优先把 Kruskal+DSU 写稳，Prim 先做到手算和区分状态。

## 写模板前必须补齐

本文代码片段展示核心，不是完整程序：DSU 必须先 `fa[i]=i`；BFS 必须先把所有距离设为 -1，再让起点距离为 0。多组输入要重置图、队列、距离和并查集。

树上仅跳过父节点的 DFS 只适用于树；普通图需要 `vis`。大规模链优先考虑显式栈，不能假定递归总安全。连通图、孤立点、重边、自环都要按题面检查。

Dijkstra 堆中距离和边权运算应使用 `long long`，选择能容纳最大路径且加法不溢出的 INF；不能用于负权。多源 BFS 把所有起点距离设 0 并去重入队，不要真的给普通 BFS 添加零权边。

## 手算与验收

- DSU：依次合并 1–2、2–3，询问 1–3 为同组、1–4 为不同组；重复合并不改变集合。
- Kruskal：边 `(1,2,1),(2,3,2),(1,3,5)`，答案 3；只有 `(1,2,1)` 而 n=3 时不连通。
- BFS：边 1–2、2–3、1–3，起点 1，到 3 为 1 步；再加孤立点 4，其距离为 -1。
- Dijkstra：有向边 1→2=2、1→3=7、2→3=1，从 1 到 3 为 3；说明为何不是按最少边数选择。
- DFN：根 1、边 1–2、1–3、2–4，节点 2 子树恰有两个连续编号；编号随访问顺序变化，连续性不变。
