## DP：先把“状态和转移”写对，再谈优化

### 用两件物品看清“记住过去”

每件物品只能选一次：重量与价值分别 `(2,3),(3,4)`，容量 4。定义 `dp[i][c]` 为“只考虑前 i 件、总重量不超过 c 时的最大价值”。前 0 件全为 0，因为可一件不选。

考虑第 i 件时只有两种来源：不选它，保留 `dp[i-1][c]`；能装下才选它，用 `dp[i-1][c-w]+v`。取两者较大值：

| 考虑的物品 | c=0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| 无 | 0 | 0 | 0 | 0 | 0 |
| 只有(2,3) | 0 | 0 | 3 | 3 | 3 |
| 再加(3,4) | 0 | 0 | 3 | 4 | 4 |

容量 4 装不下两件，总价值不能是 6 或 7。这张表保留了后面决策需要的“前 i 件、可用容量 c”，不必记每个具体选法。

若改成“**恰好**装到 c”，不能全初始化为 0：只有容量 0 可达，其余不可达。这不是同一张状态表，不能直接照搬初值。朴素版 O(nC) 时间、O(nC) 空间。

第 4 节课的顺序很适合考场落地：

```text
复杂决策
→ 拆状态
→ 写朴素 DP
→ 手算验证
→ 算时间 / 空间
→ 找真正瓶颈
→ 只优化瓶颈
```

### 定义状态的四问

看到 `dp[i][j][k]`，每一维都必须能用一句人话解释：

- `i`：做到第几步 / 前多少个？
- `j`：当前数量 / 位置 / 资源？
- `k`：还必须记住的额外条件？
- 如果删掉这一维，下一步还能正确转移吗？

**说不清某一维，就先不要抄转移式。**

### 考场第一版允许很慢

例如：

```cpp
for (int i = 1; i <= n; ++i)
    for (int j = 0; j <= m; ++j)
        for (int k = 0; k <= m; ++k)
            dp[i][j] = max(dp[i][j], old[k] + gain(k, j));
```

哪怕是 O(nm²)，只要能过小数据，它本身就是：

1. 部分分程序；
2. 正解推导起点；
3. 后面优化版本的对拍程序。

### 现在只学三种便宜优化

#### 先确认内层循环重复做了什么

**前缀和优化**：若计数转移为 `new[j]=old[j-1]+old[j-2]+old[j-3]`，对 old 做前缀和 P，便能用 `P[j-1]-P[j-4]` 代替三项相加。真正收益在允许转移范围很长时显现；越界端点要裁剪，取模题减法需规范化。

**最值维护**：转移 `dp[i]=value[i]+max(dp[0…i-1])`，计算 i 前存着 best，先用它求 dp[i]，再把 dp[i] 加入 best。若先加入再计算，会让当前状态依赖自身。若候选是滑动窗口，旧值会过期，不能一直保留全历史 best。

**滚动数组**：上面的背包只用前一行，所以两行就够；进一步变成一行时，容量必须倒序。仅有物品 `(2,3)`、容量 4，若正序，c=2 刚更新为 3，c=4 就拿它再加 3 得 6，等于同一物品用了两次。倒序才能读到上一层的值。

这些优化分别减少重复求和、重复找最值、存储层数；不能因为都叫 DP 优化就混用。

**前缀和优化**：内层循环反复算区间和 / 区间是否存在 → 预处理后 O(1)。

**bitset 优化**：状态只有 true/false，转移能写成整体 OR / AND / 移位 → 一次并行处理很多位。

```cpp
bitset<5005> f;
f[0] = 1;
f |= (f << w);
```

把它理解成“整排布尔状态一起移动并合并”，不要当魔法模板。

**最值维护**：内层循环只是为了找 `max/min` → 想能否维护“目前最优值”，去掉一层枚举。

另外，若第 i 层只依赖第 i-1 层，优先考虑**滚动数组**省空间。

### 当前不要追的 DP 优化

斜率优化、四边形不等式、根号分治、复杂单调队列优化等，先认识名字即可。它们不能挤占 T1/T2 基础、朴素 DP 和部分分训练时间。

## `bitset`：一次处理很多布尔值

### 一位代表一个“可不可以”

把每一位想成开关：第 j 位亮，表示和 j 可达。初始只有 `{0}`；加入重量 2，`f<<2` 把原来亮着的 0 搬到 2，合并后 `{0,2}`；再加入重量 3，把旧 `{0,2}` 搬到 `{3,5}`，合并得 `{0,2,3,5}`。

移位只是批量表达“给每个旧答案加同一个重量”，不是在计算数值 0+2+3+5。`f |= f << w` 里旧 f 的可达状态整体移一次，所以每件物品这一轮只用一次。

集合 A={1,3}、B={3,4}：`A&B` 是共同的 {3}，`A|B` 是 {1,3,4}，`A^B` 是只在一边的 {1,4}；count 数亮位，test 看某位，set/reset 开关某位。打印位串通常从高位到低位，不要把显示方向误当下标方向。

布尔集合可按机器字并行运算，但容量仍占内存，移位也不是与容量无关的 O(1)。实际收益取决于状态数、实现和操作方式。

最小认识：

```cpp
bitset<2000> a, b;

auto both = a & b;
int common = both.count();
```

适合：

- 集合交并；
- 共同邻居；
- 布尔可达性；
- 某些状态转移加速。

现在只要求认识 `set/reset/test/count/&/|/^/<< / >>`，不要为了“高级”强行使用。

## DP 写前检查卡

| 要素  | 必须写出的内容                           |
| --- | --------------------------------- |
| 状态  | 每一维是什么；表示恰好还是至多；是否包含当前元素          |
| 初值  | 哪些状态可达；最大化用负无穷、最小化用正无穷；计数空方案是否为 1 |
| 转移  | 从哪些合法旧状态来；每个元素能用一次还是多次            |
| 顺序  | 依赖是否已计算；滚动数组是否覆盖还要用的旧值            |
| 答案  | 指定状态还是一组状态取最值；是否需要取模              |
| 复杂度 | 状态数 × 每状态转移数；数组元素数 × 单元素字节数       |

不可达状态不要直接拿来加代价，先检查。最值维护要证明候选集合如何随 i 改变；候选会失效时不能永久保留一个历史 best。

## 0/1 背包与 bitset 的区别

每个重量只用一次、只问能否凑成和：标量布尔 DP 的容量应从大到小更新；bitset 的 `f |= f << w` 使用移位表达式产生的新集合，再与旧集合合并。它不能直接求最优价值或方案数。

`bitset<5005>` 仅保存下标 0–5004。若需更大和必须先调整容量；超出位会被丢弃。滚动数组每轮需要正确清空或继承，不能套一个初始化方式处理所有 DP。

## 手算验收

重量 `[2,3]`，和 0、2、3、5 可达，4 不可达。再加一个重量 2 后，4 才可达。用该反例检查是否误把一次物品用多次。

最大非空子段和：`[-5,-2,-8]` 的答案是 -2，不能把空子段的 0 当答案；这也是 [对拍范例](../../../CSP-JS通用/复赛通用/对拍模板/README.md) 的故障练习。

闭卷写出一种朴素 DP，与小规模穷举核对；记录状态、初值、循环方向后才做优化。
