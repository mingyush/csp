## 区间问题：先选最简单够用的工具

看到“区间”不应该直接跳到线段树，而是先走选择器：

```text
静态区间和
→ 前缀和

多次区间加，最后统一求结果
→ 差分

静态区间 max/min/gcd，查询很多
→ ST 表

有单点修改 + 区间查询
→ Fenwick / 线段树

区间修改 + 区间查询
→ 线段树 + lazy

二维矩形覆盖
→ 扫描线（当前先认识）
```

### ST 表最低掌握

#### 把区间拆成两个已经存好的块

数组 `[1,5,2,4,3]`。`st[2][1]` 存位置 2 起长 2 的最大值，即 max(5,2)=5；`st[2][2]` 长 4，可合并 `[2,3]` 与 `[4,5]`，仍为 5。

查询 `[2,4]`，长度 3，取不超过 3 的最大二次幂 2：用 `[2,3]` 与 `[3,4]` 的最大值再取 max，得 5。位置 3 重叠了，但 max(2,2)=2，不影响答案；求和就会重复计算，所以不能照用。

预处理 O(n log n)，查 max/min 为 O(1)，空间 O(n log n)。一旦修改某元素，许多块都过时，因此用于静态数据。

`st[i][k]` 表示从 i 开始、长度 `2^k` 区间的信息。

```cpp
st[i][k] = max(st[i][k-1],
               st[i + (1 << (k-1))][k-1]);
```

可争取的目标：静态 max/min 查询能独立写。

### 线段树最低掌握

#### 区间一分为二，每个节点保存一份摘要

数组 `[1,5,2,4]`，根管 `[1,4]`、和为 12；两孩子管 `[1,2]`、和 6，与 `[3,4]`、和 6；再往下才是单个元素。

查 `[2,4]`，左边取位置 2 的 5，右边 `[3,4]` 整段取 6，合并得 11，不必再看右边每个数。把位置 3 赋成 10，只改其叶子及一路祖先，根和变 20，查询 `[2,4]` 变 19。

build 是建摘要；push_up 用两个孩子更新父亲；update 沿有关分支改；query 遇到完整覆盖直接用摘要。建树 O(n)，单点修改、区间查询 O(log n)。

lazy 是区间修改的接续思想：长度 L 的整段都加 x，区间和立即加 x·L，并记下“孩子以后也要补 x”。访问孩子前再下传；不是把修改忘掉。现阶段先把单点版写清，不急着混入标记。

先只会：

- build；
- push_up；
- 单点 update；
- 区间 query。

区间 lazy 在这四个动作稳定后再补。扫描线不进入近期必写模板。

## 字符串：先暴力、会构造，再学哈希/Manacher

第 2 课强调 Manacher、序列哈希、集合哈希，但不按“课程讲几个算法就背几个模板”。

### 第一反应

```text
字符串题
→ 先写朴素比较 / 模拟
→ 主动构造边界样例
→ 如果重复比较长子串太慢，再想哈希
→ 如果大量回文中心扩展重复，再认识 Manacher
```

### 哈希最低掌握

#### 把一长串变成便于比较的指纹

令 a=1、b=2、c=3，为了手算先取 B=10、不取模：`abc` 指纹为 `1×100+2×10+3=123`。前缀指纹 H 的更新是 `H[i]=H[i-1]×B+字符值`。

想取 bc，可从 123 减掉 a 所占的 100，得到 23：一般子串 `[l,r]` 指纹为 `H[r]-H[l-1]×B^(r-l+1)`。前缀哈希与幂预处理 O(n)，一次子串比较常用 O(1) 指纹比较。

实际不能让数字无限增长，需选模数或规范的无符号运算方案。取模会压缩不同字符串到有限指纹，例如手算示例对 100 取模时，aab=112 与 bab=212 都成 12。双哈希可降低冲突概率，也不构成绝对相等证明；有符号整数溢出不能当合法取模。

**序列哈希看顺序**，ab 与 ba 通常不同；**集合哈希希望忽略顺序**，例如把各元素指纹做异或。异或会让重复元素抵消，因此这种简单方案不能直接表达任意多重集合。先确认是字符串、集合还是含重复的多重集合。

知道用途：

> 把一段长字符串 / 序列变成一个短指纹，加速重复相等比较。

同时记住：

> 哈希有冲突风险，不是数学上的绝对相等证明。

### Manacher 当前目标

#### 先看暴力为什么重复

`ababa` 以位置 2 的 b 左右扩，可以得到回文 aba；以位置 3 的 a 扩可得到整个 ababa。中心枚举法每次从头比较，在 `aaaaa…` 上会反复比较大量相同片段，最坏 O(n²)。

Manacher 维护“当前已知伸得最靠右的回文”。新中心如果在这个回文内，可先参考它关于大中心的镜像位置：已证实的对称部分不用重比。但可直接借用的半径不能越过已知右边界，超过部分仍要逐字符扩展。

如 `abacaba` 是以位置 4 为中心的回文，位置 6 的镜像是位置 2；可参考位置 2 的回文半径，仍受右边界 7 限制。新增比较使最右边界只向右推进，总体能做到 O(n)。

奇数回文中心在字符上（aba），偶数中心在字符间（abba）。不同模板的半径是否含中心、左右端点是否包含不同，不能混公式。**现在的理解目标**：能画出中心与镜像，并说明为何只能借到右边界；尚不要求背模板。

能解释：

- 暴力枚举中心如何扩展；
- 已经求出的回文半径为什么能帮助新中心；
- 奇偶回文的区别。

现在不要求闭眼默写完整模板。

## 区间结构的关键限制

ST 表的两段查询通常有重叠，因此直接拼两段适用于 max/min/gcd 这类重复合并不改变结果的运算，不能用同一公式求和。先预处理整型 `lg[len]`，避免浮点 log 的边界。

单点修改与区间求和也可以用 Fenwick；现有范例采用线段树，不表示所有区间题都必须用线段树。先检查内存预算，再选择结构。

## 最小验收

| 工具 | 输入操作 | 应得到 |
| --- | --- | --- |
| ST 最大值 | `[1,5,2,4,3]` 查询 `[1,3]`、`[2,5]`、`[4,4]` | 5、5、4 |
| 单点修改区间和 | 同数组，先查 `[2,4]`，再把位置 3 赋为 10，再查 `[2,4]` | 11、19；赋值不是加 10 |
| 回文暴力 | `a`、`aa`、`aba`、`abca` 整串判断 | 真、真、真、假 |
| 子串相等 | `ababa` 的 `[1,3]` 与 `[3,5]` | 相等；约定下标从 1 开始 |

字符串还要测：长度 1、全相同、全部不同、重叠匹配、匹配到最后一位、不存在答案。正向条件与否定条件都需验证；“要求匹配的位置全部匹配”不等于“要求不匹配的位置都不匹配”。

先用逐字符比较作独立基准；哈希相等只表示指纹相等。Manacher、集合哈希目前保持认识层级，不能默认已能考场实现。
