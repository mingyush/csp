## 2020 T1 P7075《儒略日》：复杂模拟先分段

**工具触发：模拟、边界、分段处理。**

这题的价值不在背历法，而是训练：规则很多时，不要把所有 if 塞进一个大循环；按时间段拆开。

### 第一版

如果子任务中的日期范围较小，直接从起始日期一天一天模拟：维护年、月、日，写 `days_of_month(year, month)`，单独处理闰年，每走一天更新日期。

即使大数据过不了，这也是小数据部分分，也是后续优化的正确性基准。

### 再优化一层

不要按“天”跳，改为先按大周期跳，再按年、月、日逐级缩小。先把分段边界写正确，再追求快。

### 什么时候停

如果历法切换、闰年规则已经占用太多时间，优先保证明确的小范围正确，不为了 T1 名字硬耗整场。

## 2020 T2 P7076《动物园》：小 k 就枚举整个状态空间

**工具触发：二进制、bitmask、小参数。**

动物编号本来就是 k 位二进制。若 k 小，第一版直接枚举所有动物编号：

```cpp
// 仅在 k 足够小、k < 64 且总枚举量可承受时使用
for (unsigned long long x = 0; x < (1ULL << k); ++x) {
    // 检查加入 x 后是否会新增必须购买的饲料
}
```

这就是工具箱里的小参数思想：不要只盯 n/m，先看 `2^k` 是否可做。

最低掌握：会用 `x >> p & 1` 判断第 p 位，会用整数表示集合。

## 2021 T1 P7913《廊桥分配》：先写“给定 x 个廊桥能接多少”

**工具触发：排序、优先队列、模拟、预处理。**

### 第一版

先解决一个小问题：国内固定给 x 个廊桥，最多能停多少国内航班？

按到达时间排序，用最小堆维护当前已占用廊桥的离开时间；飞机到达时弹出已经离开的，如果占用数 < x 就接纳。

然后枚举 `国内 x 个 + 国际 n-x 个`，求最大值。这个版本可能慢，但思路清楚。

### 再优化一层

一次模拟时给廊桥编号，统计“使用前 i 个廊桥一共能接多少航班”，得到两类航班的前缀答案，再枚举分配数即可。

重点：先写正确的 `calc(x)`，再想怎么把很多次 calc 合并。

## 2021 T2 P7914《括号序列》：多维 DP 代表题，但不是近期硬切题

**工具触发：区间/多维 DP、前缀和优化。**

这正是第 4 课用来说明复杂状态的代表。当前目标不是完整 AC，而是能回答：所选定义下 `dp[l][r]` 记录了什么、组合转移还需要区分哪些类别、连续 `*` 长度为什么是约束、前缀和消掉哪类重复判断。

### 考场第一版

先保留朴素状态和朴素转移。若小 n 子任务允许，接受高复杂度区间 DP；它既是部分分，也是后续优化的基准。

### 什么时候停

如果状态都解释不清，不要背完整多状态模板，把时间留给 T1、其它 T2 和更直接的部分分。

## 2022 T1 P8817《假期计划》：先把“能否在 k+1 条边内到达”预处理出来

**工具触发：BFS + 枚举 + 预处理。**

行程为 `1 → A → B → C → D → 1`，每段最多转车 k 次，等价于图上距离不超过 `k+1` 条边。

### 第一版

从每个点 BFS，得到 `can[u][v] = (dist(u,v) <= k+1)`；小数据直接枚举四个不同景点 A/B/C/D 并检查五段可达性。

复杂但正确，非常适合作为部分分和对拍程序。

### 再优化一层

真正需要枚举的是中间 B、C；A、D 从候选中取分数最大的少数几个。核心思想：如果最后只会冲突少数对象，就不必保留所有候选，只保留前几名。

## 2022 T2 P8818《策略游戏》：先写 O(A 区间长度+B 区间长度) 查询，再升级 ST 表

**工具触发：分类讨论、区间最值、ST 表。**

### 第一版：每个查询直接扫

先扫描 B 查询区间得到 `minB, maxB`，再扫描 A：A[x] >= 0 时后手选 minB，A[x] < 0 时后手选 maxB。

```cpp
long long ans = -INF;
for (int x = l1; x <= r1; ++x) {
    long long worst = (A[x] >= 0 ? 1LL * A[x] * minB : 1LL * A[x] * maxB);
    ans = max(ans, worst);
}
```

这是很适合的“先把博弈翻译成人话”方案。

### 再优化到大数据

真正有用的 A 候选只有最大/最小正数、最大/最小负数以及 0 是否存在；这些都是静态区间最值查询，正好接第 3 课 ST 表。

## 2023 T1 P9752《密码锁》：整套模拟后再看

**工具触发：小状态空间、枚举、check。**

五个拨轮，每位 0~9，总密码数只有 `10^5 = 100000`。

### 推荐方案

直接枚举 00000~99999，每个候选密码检查能否通过一次合法转动得到题目给出的每个状态。合法操作只有：转一个拨轮任意非 0 幅度，或转两个相邻拨轮相同幅度。

```text
枚举候选密码
→ 对每个观测状态 check
→ 所有状态都能由候选产生，答案 +1
```

这是最应该建立的信心：**看到 100000 个候选时，不要因为是 CSP-S T1 就强行找高级算法。**

验证方式：随机生成候选密码和若干观测状态，再用两种 check 写法互相对拍。

## 2023 T2 P9753《消消乐》：整套模拟后再看

**工具触发：字符串模拟、栈、重复计算。**

一个子串能消空，可以用栈判断：当前字符和栈顶相同就弹出，否则压入；最后栈空则可消除。

### 最笨但可靠版

枚举 `[l,r]`，每个子串重新跑一次栈，复杂度 O(n³)。只适合很小数据，但非常适合当对拍 brute。

### 更推荐的 O(n²) 版

固定左端点 l，只维护一个栈，然后 r 从 l 向右扩：

```cpp
for (int l = 0; l < n; ++l) {
    vector<char> st;
    for (int r = l; r < n; ++r) {
        if (!st.empty() && st.back() == s[r]) st.pop_back();
        else st.push_back(s[r]);
        if (st.empty()) ++ans;
    }
}
```

这就是“不要重复从头算”的典型优化。大数据仍过不了，但比直接学复杂哈希/线性做法更符合考场落地能力。

## 2024 T1 P11231《决斗》：先找不可消除的下界

**工具触发：排序/计数、构造、贪心证明。**

每只怪兽至多攻击一次且击破对象必须严格更弱，因此有效攻击关系可以看作若干条严格递减的链。相同攻击力不能在同一条链中，出现次数最多的值要求至少这么多条链；每条链可从弱到强安排攻击，最后留一只。排序后可构造恰好这么多条链，故答案为最大出现次数。注意不是“同值怪兽都不会被别的怪兽击破”。

### 推荐实现

最稳的是排序后统计最大连续相同段：

```cpp
sort(a.begin(), a.end());
int ans = 1, cur = 1;
for (int i = 1; i < n; ++i) {
    if (a[i] == a[i-1]) ++cur;
    else cur = 1;
    ans = max(ans, cur);
}
```

这题非常适合训练：**先证明一个必须留下多少的下界，再想能不能构造到这个下界。**

## 2024 T2 P11232《超速检测》：先 O(nm) 暴力，再变成区间

**工具触发：公式、区间、二分、贪心。**

### 第一版：先做第一问

对每辆车枚举所有位于其进入位置之后的测速仪 p，用平方速度公式判断：

```text
v(p)^2 = v0^2 + 2*a*(p-d)
```

若存在测速仪满足 `v(p)^2 > V^2`，这辆车会被检测到。O(nm) 很慢，但逻辑直接，可拿小数据，也能做后续程序的 brute。

### 再优化一层

一辆车能被测出超速的测速仪位置一定形成连续区间。于是：

```text
每辆超速车 → 一个测速仪下标区间 [L,R]
```

第一问变成“这个区间里是否存在测速仪”；第二问变成“每个区间至少保留一个点，最少保留多少测速仪”。

后一问是经典区间贪心：按右端点排序，尽量选最靠右的测速仪覆盖更多后续区间。

O(nm) 第一问可作推导与对拍模块，但不能直接承诺得分。小 m 时枚举保留测速仪子集，同时验证全部被测超速车辆仍被覆盖，从而答全两问；完整输出与时限都满足后才是可交的子任务版本。减速车辆还需检查能否真正到达测速点，不能只代入负的速度平方。

## 2025 T1 P14361《社团招新》：先取最好，再用最小损失修正

**工具触发：贪心、排序、反悔。**

先忽略人数限制，让每个人去满意度最高的部门。因为总人数是 n，而每个部门上限 n/2，所以此时最多只有一个部门会超员。

若部门 d 超员，就把其中一部分人转到另外两个部门之一。对每个当前在 d 的人，计算离开 d 的最小损失：

```text
loss_i = best_i - max(other1_i, other2_i)
```

把 loss 从小到大排序，转走需要的人数即可。

### 为什么值得完整学

它把“反悔贪心”变得非常直观：

```text
先做局部最优
→ 发现违反容量限制
→ 从已选项里挑损失最小的几个撤回/修改
```

这是 `sort` / `priority_queue` 的高收益实战。

## 2025 T2 P14362《道路修复》：先拿 k=0，再认识 2^k

**工具触发：DSU、Kruskal、小参数。**

### 第一目标：k=0

没有乡镇改造时，题目就是：从原有道路中选一些修复，让 n 座城市全部连通且总费用最小。

直接 Kruskal：

```text
边按费用排序
→ DSU 判断两端是否已连通
→ 不连通就选
→ 选够 n-1 条
```

这是当前最适合把课堂 DSU/Kruskal 落到真题的一部分。

### 对拍方案

限制 `n<=6, m<=10`，暴力枚举边子集：只检查选 `n-1` 条且连通的集合，取最小费用；与 Kruskal 随机对拍。

### 第二层：看到 k<=10 要有反应

`2^10 = 1024`，所以自然想到枚举“哪些乡镇进行城市化”。

对每个选择集合重新求一棵包含相应新点/新边的 MST，是一个非常自然但未必能通过最大数据的进一步方案。对备考者来说，这已经完成了最重要的建模：

```text
小参数枚举
+
已有成熟算法 Kruskal
```

## 完整最优解还需要进一步减少每个集合重复处理的边，不作为当前必须掌握。
