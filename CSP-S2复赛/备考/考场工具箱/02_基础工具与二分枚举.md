## `vector + pair + range-for`

### 先把这句类型读成人话

`vector` 是会按需要增长的一排格子；`pair<int,int>` 是把两个整数捆在一起。例如道路“从 1 到 3，长度 7”，可在 `g[1]` 里放 `(3,7)`。

```text
有边 1—2，长度4；1—3，长度7：
g[1] = [(2,4), (3,7)]
g[2] = [(1,4)]
g[3] = [(1,7)]
```

`vector<vector<pair<int,int>>> g(n+1)` 就是“n+1 个点，每个点有一份邻居清单，清单每项记邻点与边权”。开 n+1 是为了使用编号 1…n，0 号通常空着。

`push_back` 是往清单末尾加一项；`for (auto [v,w] : g[u])` 是把 u 的每个邻居条目依次拆成 v、w。它不会自动找遍整张图，只遍历 u 的直接邻居；DFS/BFS 才负责继续走。

**自己说一遍**：有向边 2→3、长度 5，应只改哪张清单？答案是 `g[2]`；无向边才补反方向。

### 什么时候想到

- 图、树、边很多但规模不是极端内存题；
- 数据数量运行时才知道；
- 希望代码短、少写数组下标。

### 最小图模板

```cpp
vector<vector<pair<int,int>>> g(n + 1);

g[u].push_back({v, w});
g[v].push_back({u, w});  // 无向图

for (auto [v, w] : g[u]) {
    // 使用邻点 v 和边权 w
}
```

### 要注意

- 无向边通常要加两次；
- 树上 DFS 可以传 `parent`，少一个 `vis[]`；
- 若题目边数达到百万级且内存吃紧，再考虑扁平数组，不必平时先学复杂写法。

## `sort`、双指针、`unique`、`lower_bound`

### 排序到底帮我们省掉什么

原数组 `[40,10,40,20]` 排成 `[10,20,40,40]` 后，相同值挨在一起、比某个值小的数都在左边。排序一次 O(n log n)，后面很多判断就能从“到处找”变成“沿有序方向移动”。

`unique` **只把相邻重复项挤到后面，并返回新的逻辑结尾，不会真的缩短 vector**；所以先排序，再 `erase(unique(...),end())`。去重后是 `[10,20,40]`。

`lower_bound(...,25)` 返回第一个不小于 25 的位置，即值 40 的位置；找 50 则返回 `end()`，不能解引用。若想找“第一个大于 x”，用 `upper_bound`。

### 离散化：给大数发小编号

原值 `[40,10,40,20]`，用排序去重表 `[10,20,40]` 编号 0、1、2，变成 `[2,0,2,1]`。相等与先后关系保留，但距离不保留：编号 2 与 1 只差 1，原值 40 与 20 差 20。

### 双指针：为什么敢排除一整批候选

在有序数组 `[1,2,4,7]` 找两个不同位置的数，和为 6。左右指针从 1、7 开始：和 8 太大，左边已经最小，再增大左边更不可能，所以把右端 7 排除；变成 1+4=5 太小，右边已经是剩余最大，再缩小右边更不可能，所以排除左端 1；最后 2+4=6。

关键是每次移动都说明“丢掉的候选为什么不可能有答案”。两个指针各走至多 n 步，排序后扫描 O(n)，不是两层循环 O(n²)。**反问自己**：数组没排序，还能作出这些排除吗？不能。

排序经常不是最后一步，而是**把混乱关系变成有序关系**。

### 去重

```cpp
sort(a.begin(), a.end());
a.erase(unique(a.begin(), a.end()), a.end());
```

### 离散化找编号

```cpp
vector<int> b = a;
sort(b.begin(), b.end());
b.erase(unique(b.begin(), b.end()), b.end());

int id = lower_bound(b.begin(), b.end(), x) - b.begin();
```

### 触发器

看到“值很大但只有 n 个”“只关心大小关系”“要找第一个 >= x”，先想排序 + 二分，不要第一反应上 `map/set`。

## 前缀和：重复统计先预处理

### 先手算，再看公式

数组 `a=[2,-1,3,4]`，先记“从头到这里一共多少”：

| 位置 i | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| pre[i] | 0 | 2 | 1 | 4 | 8 |

求 `[2,4]`：前四项 8，减去不想要的第一项 2，得 6，所以是 `pre[4]-pre[1]`。`l-1` 表示“左边界之前”，不是随手背的减一。

负数不影响这个相减关系。建表 O(n)，每次查询 O(1)；若数组中途改动，后面的前缀和会过时，不能不更新还照查。

二维也是去掉矩形外的部分：`S[x2][y2]-S[x1-1][y2]-S[x2][y1-1]+S[x1-1][y1-1]`。左上角被减两次，需加回来；先画四格再记公式。

一维区间和：

```cpp
pre[i] = pre[i - 1] + a[i];
long long sum = pre[r] - pre[l - 1];
```

二维矩形和本质相同：把重复的 O(n) / O(n²) 统计提前算掉。

### 问题触发器

> “同一批数据要被问很多次，能不能先算一次？”

这比背公式更重要。

## 差分：很多区间修改不需要线段树

### 为什么只改两个位置就能影响整段

把 diff 当作“走到这里，新增影响增加多少”。给 `[2,4]` 加 3，只需在位置 2 写“从此多 3”，位置 5 写“从此少 3”：

```text
位置：        1  2  3  4  5
diff：        0 +3  0  0 -3
走到此处的cur：0  3  3  3  0
```

`r+1` 是区间结束后的第一个位置，放在那里才不会把第 r 项的影响提前撤掉。再给 `[1,2]` 加 -1，只需叠加 `diff[1]-=1, diff[3]+=1`，不同操作互不冲突。

这里 diff 记录的是**新增修改**，所以恢复后加到原 a 上；另一种写法把原数组本身存成相邻差，那就直接恢复数组。两种写法不能混在一起。

q 次修改加一次恢复是 O(q+n)；若每次修改后立刻查询，重新恢复 q 次就失去优势。

若多次执行“区间 [l,r] 全部 +x”，可以只改两个端点：

```cpp
diff[l] += x;
diff[r + 1] -= x;
```

最后一次前缀累加恢复：

```cpp
long long cur = 0;
for (int i = 1; i <= n; ++i) {
    cur += diff[i];
    a[i] += cur;
}
```

### 核心判断

如果题目是“很多次修改，最后统一看结果”，差分往往比动态数据结构简单很多。

## 二分答案：把“求最优”改成“判断行不行”

### 一次完整手算：最小箱子容量

物品重量 `[2,3,4]`，顺序不变，每箱放连续一段，至多两箱。直接求最小容量难一点，但给定容量 C 后可从左到右装：装得下继续，装不下开下一箱。

| 容量 | 一种装法 | 是否至多两箱 |
| --- | --- | --- |
| 4 | `[2] [3] [4]` | F |
| 5 | `[2,3] [4]` | T |
| 6 | `[2,3] [4]` | T |
| 9 | `[2,3,4]` | T |

容量增大，可以沿用原来可行的分法，因此不会从 T 变回 F。这才是单调性证明。对这道题，正重量还保证“当前箱尽量装满”的 check 使用箱数最少；**二分正确和 check 正确是两件都要证明的事**。

取 l=4、r=9：mid=6 可行，令 r=6；mid=5 可行，令 r=5；mid=4 不可行，令 l=5，得到 5。

每轮保留“最小可行值一定在 `[l,r]`”这个不变量。若搜索“最大可行值”，可行方向和中点取整都需重新设计。总复杂度为 O(check 的成本 × log 搜索范围)。

### 高频触发器

- 最大的最小值；
- 最小的最大值；
- 最早多少天能完成；
- 最少容量是多少；
- 若答案为 x 可行，更宽松的答案一定也可行。

先写：

```cpp
bool check(long long x) {
    // 如果答案限制为 x，能不能完成？
}
```

再二分：

```cpp
long long l = 0, r = LIMIT;
while (l < r) {
    long long mid = l + (r - l) / 2;
    if (check(mid)) r = mid;
    else l = mid + 1;
}
cout << l << '\n';
```

### 真正难点

不是二分代码，而是证明 `check(x)` 有单调性。

### 学习方式

先做“手算 5 个候选答案，写出 True/False 序列”。如果不是类似：

```text
F F F T T T
```

就不能直接二分。

## 小参数枚举 / bitmask：不要只盯着最大的 n

### 一个整数怎样代表所有选与不选

有 A、B、C 三个特殊对象，约定最低位对应 A，第二位 B，第三位 C。mask=5 的二进制是 `101`，表示选 A、C，不选 B；mask=0 表示一个都不选，mask=7 表示全选。

`(mask >> i) & 1`：先把第 i 位搬到最低位，再只看这一位是 0 还是 1。i 从 0 起，所以 A 对应 i=0。

三项有 8 种集合；两项有 4 种，新增一项让每种旧集合多出“选/不选”两种，所以总数是 `2^k`。

枚举所有集合并检查每个元素，成本 O(k·2^k)；若每个集合还跑 Kruskal，必须乘上 Kruskal 的成本。**理解题**：把选法用 mask 表示，是否就叫状压 DP？不是；还需要重复子问题、状态和转移才是 DP。

这是最值得提前拥有的“NOI 式低成本思维”。

看到：

```text
n <= 100000
k <= 10
```

不要只看到十万，要马上计算：

```text
2^10 = 1024
```

枚举集合：

```cpp
for (int mask = 0; mask < (1 << k); ++mask) {
    for (int i = 0; i < k; ++i) {
        if (mask >> i & 1) {
            // 第 i 个特殊对象被选择
        }
    }
}
```

常见套路：

```text
枚举小参数的所有选择
+
每一种选择调用一个自己已经会的算法
```

例如：

- 枚举特殊点 + 最短路；
- 枚举乡镇 + MST；
- 枚举开关 + check。

**这不是要求现在就学复杂状压 DP。先会“用二进制表示选/不选”就够。**

## 边界与适用条件补充

- 离散化保留大小与相等关系，不保留实际距离；坐标差仍需用原值。
- 双指针需要证明移动不会漏解。含负数的区间和不能直接套“超了就缩左端点”。
- 差分数组至少开到 `n+2`；若存原数组差分，恢复时直接前缀累加，不要再加一次原值。
- 二分片段仅用于 `F…F T…T` 且右端点已知可行、答案存在的情况；全不可行要先处理。求最大可行值不能原样套用。
- `1<<k` 有位宽和符号风险；`1ULL<<k` 也要求 `k<64`。即便移位合法，枚举仍须估算 `2^k × 每状态工作量`。
- C++17 才支持结构化绑定 `auto [v,w]`；若使用 C++14，写 `for (const auto &e : g[u]) { int v=e.first, w=e.second; }`。
