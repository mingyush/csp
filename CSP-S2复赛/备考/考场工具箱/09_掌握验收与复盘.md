# 掌握验收与复盘

> 工具箱提供验收方法与复盘口径，不记录成绩。等级只是掌握程度描述，不是分数。

## 三轮用法

这套材料不适合从头刷到尾。三轮的差别只在"打开哪几页"：

| 轮次 | 做什么 | 花多久 |
| --- | --- | --- |
| 第一轮 | 只过触发器：题面关键词能联想到 1–2 个工具 | 10–15 分钟 |
| 第二轮 | 每个工具只做一个最小例子：手算 → 关掉说明实现 → 边界复测 | 每个 20–30 分钟 |
| 第三轮 | 用真题检验触发器，一次只挑一个工具是否被正确唤起 | 按卷面时间 |

第二轮的工具本身有先修关系：排序去重与 `lower_bound` → 前缀和／差分 → DFS/BFS → DSU/Kruskal → 二分答案 → 朴素 DP → 暴力与对拍。ST、线段树、字符串哈希、bitset 属于接续项，缺失先修时先补先修，而不是背模板。

## 一分钟决策单

拿到题后依次问：

1. 数据范围最小的点能怎么暴力？
2. 有没有 `k<=10/15/20` 之类的小参数？
3. 是静态还是动态？能不能前缀和／差分／ST，而不是线段树？
4. 是连通关系吗？DSU？最小连通费用吗？Kruskal？
5. 是最优值且有单调性吗？二分答案？
6. 是 DP 吗？先写朴素状态和转移，不先想优化。
7. 内层循环在重复求区间和、布尔集合、max/min 吗？对应前缀和、bitset、最值维护。
8. 正解写出来不放心吗？能否写一个小数据 brute 对拍？
9. T3/T4 二十分钟没有稳定方向时，先交可靠部分分，回头保 T1/T2。

> 目标不是"我会很多算法"，而是"每道题我都能迅速找到一个自己真的写得出来的版本"。

## 一次训练怎样算通过

1. **解释**：独立说出状态／不变量、成立条件、时间与空间复杂度。
2. **手算**：至少一个正常例、一个边界例、一个能打破错误写法的反例。
3. **实现**：关掉参考写最小版本，自己编译运行；代码片段不能当完整程序照抄。
4. **回归**：重跑旧反例与已有测试数据，记录实际结果，不用参考档位代替。
5. **隔日复测**：次日重做一遍；只有当天看答案写出来，不算稳定。

## 两级记录

| 记录项 | 取值 | 用途 |
| --- | --- | --- |
| 掌握等级 | 0 只听过／1 看懂例子／2 能手算解释／3 关说明独立写并自测 | 描述当前水平 |
| 提示级别 | P0 独立／P1 提醒关键条件／P2 给小例或反例／P3 指出状态与关键步骤／P4 看过接近完整实现 | 描述这次是怎么写出来的 |

两者必须分开填。"P4 写出来 + 记成 3"是最常见的自欺；正确的写法是"P4，等级待复测"。未验证的项写"待验证"，不要填 0 分或已会。

```text
日期 / 题目或工具：
提示级别 / 掌握等级：
原始错误与反例：
源码位置 / 编译环境：
复测数据与实际结果：
隔日闭卷结果（未做写待复测）：
下一步只做一件事：
```

## 复盘：证据边界

复盘的对象是**可定位的证据**，不是印象：

| 证据 | 怎么留 | 不能拿来当什么 |
| --- | --- | --- |
| 首答源码 | 原样保留，修复版另存 `T3_v2.cpp` 之类 | 不能因为"后来改对了"就覆盖首答 |
| 最小反例 | 输入、正确输出、原程序实际输出三列对照 | 只有失败例不足以确认修复，必须带对照例 |
| 参考档位 | 记清是"参考版本标签"，不是本人得分 | 不能把 35/60/75 这类档位相加当作目标分 |
| 评测结果 | 实际测试点与耗时 | 不能用"今天学了 ST"代替"某题独立完成并测过" |

两问的题通常要两问都对才通过该测试点，"第一问正确"不等于可得分；计分单位以当场规则为准。

复盘顺序固定：**先消除题意遗漏、输出错误与越界 → 验证小数据版本 → 再决定是否学优化**。反过来做，会把时间花在优化一个本来就错的程序上。

## 复盘时容易越界的三件事

- 只提示"补一个 `return`"就判修好——可能只修了输出流程，没修建模。
- 用"未崩溃"证明数组没越界——容量错误常在特定规模才触发，需算清上界或用地址消毒器。
- 把"某题参考版本能到某档"当成"改完必得该分"——档位是别人的实现标签，不是承诺。
