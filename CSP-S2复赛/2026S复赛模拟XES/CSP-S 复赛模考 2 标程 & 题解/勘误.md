## 一、T3：曼哈顿距离与环上弧长

### 原文表述

题解在把正方形边界映射到长度为 `4a` 的环后写道：

> 两点的曼哈顿距离恰好等于这两段弧长中的较小值，即 `dist(i,j) = min(Δ, 4a − Δ)`。

### 问题

这个等式**一般情况下不成立**，只在特定位置关系或特定判定条件下成立。

反例：正方形边长 `a = 10`，取左边中点 `(0,5)` 和右边中点 `(10,5)`。

- 曼哈顿距离：`|0−10| + |5−5| = 10`；
- 沿边界的较短弧长：走上边或下边都是 `5 + 10 + 5 = 20`；
- 两者不相等。

### 正确关系

- 两点在同一条边或相邻两条边上：较短边界弧长就是一条单调的 L1 路径，曼哈顿距离等于较短弧长。
- 两点在相对两条边上：曼哈顿距离至少为 `a`，较短弧长可能更大。以左右两边为例，纵坐标为 `y1, y2` 时：
  - 曼哈顿距离 `= a + |y1 − y2|`；
  - 较短弧长 `= 2a − |y1 − y2|`。

### 为什么原题的 check(D) 仍可用

题目中 `k ≥ 4`。把 `k` 个点放到长度为 `4a` 的环上，`k` 段相邻间隔之和为 `4a`，必有一段间隔不超过 `4a/k ≤ a`。这一段对应的两点在同边或相邻边上，曼哈顿距离等于该间隔，所以 `D > a` 一定不可行。因此只需考虑 `D ≤ a`。

当 `D ≤ a` 时：

- 同边/相邻边：两个距离相等，阈值判断一致；
- 相对边：曼哈顿距离至少为 `a ≥ D`，环上弧长也至少为 `a ≥ D`，两边都通过。

所以“环上相邻距离 ≥ D”与“曼哈顿距离 ≥ D”在本题条件下是**阈值可行性等价**，但不是普遍的距离恒等式。

### 建议改法

把原文那句改为：

> 在本题 `k ≥ 4`、只需考虑 `D ≤ a` 的判定语境下，环上相邻距离与曼哈顿距离的阈值判断等价；但不能把 `min(Δ, 4a−Δ)` 当作任意两点的曼哈顿距离恒等式。

## 二、T2：页面复杂度与调用次数

### 1. 页面实现是 `O(n log n)`，不是 `O(n)`

`模考2/T2_谁能下到100层_可视化闯关.html` 中的 `solveReverse` 在 DP 前执行了：

```js
const order = [...Array(n).keys()].sort((a, b) => h[b] - h[a]);
```

因此该实现的复杂度是：

```text
单调栈 O(n) + 排序 O(n log n) + DP O(n) = O(n log n)
```

这不是错误做法，`n = 2×10^5` 时排序完全够用；但页面此前把它写成“纯 O(n)”，表述不准确，现已统一改为 `O(n log n)`，并注明可优化到 `O(n)`。

### 2. 官方标程是 `O(n)`，但有递归深度风险

100 分标程使用记忆化 DFS：

```cpp
int dfs(int i) {
    if (i == 0) return 0;
    if (dp[i]) return dp[i];
    dp[i] = max(dfs(ls[i]), dfs(rs[i])) + 1;
    return dp[i];
}
```

每个状态只计算一次，理论复杂度 `O(n)`。但高度可能形成一条长度为 `n` 的链，递归深度可达 `2×10^5`，在部分环境下有爆栈风险。工程上可改为显式栈或拓扑排序。

### 3. “10 个状态 = 10 次调用”不准确

记忆化后：

- 不同状态只有 `n` 个，每个状态只**展开计算**一次；
- 函数仍可能被调用多次，只是命中缓存后直接返回，不再展开。

因此应写“展开了 10 个状态”，而不是“调用了 10 次”。页面已按此区分修改。

## 三、检查结论

- T2 的算法结论（反向、最近更高、DP）不变；需要修正的是复杂度与“调用/状态”的表述。
- T3 的算法在题目约束下仍可用；需要修正的是把条件性结论写成了普遍恒等式。
- 其余 T1、T4 的题解未在本次检查中发现同级别的问题。
