# 复赛防爆零与提交检查清单

> 适用范围：CSP-J2 与 CSP-S2 共用。两轮第二轮的赛制、目录结构、评测方式一致，本节规则不区分组别。
> 组别差异只体现在代码层面的陷阱深度：J 组看[复赛知识点梳理](../../CSP-J2复赛/备考/CSP-J复赛知识点梳理2025.md)，S 组另看[知识点体系与考场技巧](../../CSP-S2复赛/备考/CSP-S复赛知识点体系与考场技巧.md)第一节。

## 一、爆零的六类来源

爆零指最终得分 0，绝大多数不是算法错，而是程序根本没被正确评测。

| 来源 | 典型表现 | 自检动作 |
| --- | --- | --- |
| 文件重定向缺失 | 本地能过样例，提交后全部 0 分 | 全文搜 `freopen`，确认未被注释 |
| 文件名/目录名不符 | 评测机找不到源文件，整题记 0 | 与题面首页对照表逐字核对，含大小写 |
| 编译失败 | 全部测试点 CE | 用 `-std=c++14 -O2 -Wall` 本地编译一遍 |
| 输出格式不符 | 答案正确但判错 | 对照样例的换行、空格、大小写 |
| 越界/未初始化 | 部分点 RE 或随机错误 | 数组按上限多开 10；变量显式赋初值 |
| 写不完/忘提交 | 有思路但最后没交 | 一题一交，不集中提交 |

## 二、文件重定向

```cpp
int main() {
    freopen("problem.in", "r", stdin);
    freopen("problem.out", "w", stdout);
    // ...
    return 0;
}
```

- `.in` / `.out` 的文件名取**题目英文名**（题面首页会给出），不是 `input.txt`。
- 本地调试时可临时注释，但提交前必须恢复——这是最高频的爆零点。
- 用 `freopen` 后 `cin`/`cout` 与 `scanf`/`printf` 均可正常使用，无需改写法。
- 若某年在题面中说明"使用标准输入输出"，则以题面为准。

## 三、目录与文件结构

```
<准考证号>/
├── problem1/
│   └── problem1.cpp
├── problem2/
│   └── problem2.cpp
├── problem3/
│   └── problem3.cpp
└── problem4/
    └── problem4.cpp
```

- 顶层文件夹用**准考证号**，不是姓名、不是"新建文件夹"。
- 子文件夹用**题目英文名**，与文件名、输入输出文件名三者保持一致。
- 只交 `.cpp` 源文件。可执行文件、`.in`/`.out`、测试数据都不交。
- 大小写敏感：`Club` 与 `club` 是两个不同目录。

## 四、代码层细节

| 检查项 | 说明 |
| --- | --- |
| 数组大小 | 用 `const int N = 1e5 + 10;` 这类带上界的写法，不写裸数字 |
| 变量初始化 | 全局变量默认 0，局部变量是随机值；DP 数组初值按"0 还是 INF"想清楚 |
| 下标基准 | 0-based 与 1-based 不能混用，同一份代码里只选一种 |
| 输出格式 | 行末不多空格，最后一行带换行 |
| 调试残留 | 删掉或注释所有 `cerr`、调试用 `cout`、`printf` |
| `main` 签名 | `int main()`，结尾 `return 0` |
| 头文件 | 用 `<bits/stdc++.h>` 或逐个包含，提交版本不能缺；重名、兼容与 CE 排错见[万能头文件与命名冲突避坑](万能头文件与命名冲突避坑.md) |

## 五、复杂度与数据范围对照

写代码前先用数据范围倒推允许的复杂度，写完再回来核对一遍。

| 数据范围 | 可接受复杂度 | 常见做法 |
| --- | --- | --- |
| n ≤ 10 | O(n!) | 全排列枚举 |
| n ≤ 20—25 | O(2ⁿ)、O(2ⁿ·n) | 状压枚举、子集 DP |
| n ≤ 100 | O(n³) | Floyd、区间 DP |
| n ≤ 1000 | O(n²)、O(n² log n) | 朴素 DP、二维前缀和 |
| n ≤ 2×10⁵ | O(n log n) | 排序、二分、线段树、堆 |
| n ≤ 10⁶—10⁷ | O(n)、O(n log n) | 线性筛、单调栈、双指针 |

- 同一条数据范围下，**子任务分档**往往允许更暴力的做法，先拿部分分再优化。
- 内存限制通常 512 MB 或 256 MB：`int` 数组 1e7 约 40 MB，`long long` 翻倍；线段树按 4 倍空间开。

## 六、提交前检查清单

每写完一题，对着这份清单过一遍（约 60 秒）：

- [ ] `freopen` 两行都在，文件名与题目英文名一致
- [ ] 目录名、文件名、输入输出名三者一致，大小写正确
- [ ] 本地用 `-Wall` 编译无警告，样例通过
- [ ] 造过一组 n=1、一组最大数据
- [ ] 调试输出已清理
- [ ] `main` 返回 `int` 且 `return 0`
- [ ] 已提交到指定目录，且提交的是当前版本

## 七、应急预案

| 情况 | 处理 |
| --- | --- |
| 某题卡住超过 45 分钟 | 先写暴力拿部分分，锁定得分后再回头想正解 |
| 样例都过不了 | 逐行比对题面，检查输入格式是否含多组数据 |
| 评测结果全 0 | 优先查 `freopen` 与目录结构，不要怀疑算法 |
| 编译报错看不懂 | 删掉最近一次改动，回到上一个能编译的版本 |
| 时间只剩 15 分钟 | 停止写新代码，逐题走完第六节清单并提交 |

写好一题提交一题，不要攒到最后——集中提交是"写完了但没交上"的唯一成因。

## 八、组别补充

- **J 组**：陷阱集中在读题、模拟细节和输出格式，算法本身不难，丢分多在"看错"而非"想不到"。
- **S 组**：额外关注整数溢出（`(long long)a * b`）、递归爆栈（深 DFS × 1e5）、MLE（高级数据结构开多大算多大），详见 [CSP-S复赛知识点体系与考场技巧](../../CSP-S2复赛/备考/CSP-S复赛知识点体系与考场技巧.md) 第一节「S组特有的高危细节」。
