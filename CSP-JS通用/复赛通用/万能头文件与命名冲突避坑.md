# 万能头文件与命名冲突避坑

> 适用范围：CSP-J2 与 CSP-S2 的 C++ 编程。示例按 C++14 编写；实际编译器、语言标准和文件读写要求以当次题面与考场通知为准。

## 一、先准备能编译的模板

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    // 若题面要求文件读写，在这里添加对应的 freopen 两行。
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    return 0;
}
```

- `<bits/stdc++.h>` 是 GCC 的 libstdc++ 提供的实现头文件，不属于 ISO C++ 标准；它包含大量常用标准库头文件，但不是“所有 C++ 功能”。MSVC、macOS 默认的 Clang/libc++ 环境通常不能直接用；Clang 配合 libstdc++ 时则可能可用。
- `using namespace std;` 与包含头文件是两回事：前者影响名字查找，后者引入声明。可以保留万能头文件，改用 `std::cin`、`std::vector` 等完整名称。
- 关同步后，避免混用 `cin/cout` 与 `scanf/printf/getchar/puts`；选定一套输入输出。`freopen` 是重定向，按题面要求在输入输出前执行即可，见[防爆零清单](防爆零与提交检查清单.md#二文件重定向)。
- 头文件不会开启新语言版本。C++14 下不能因为包含了它就使用 C++17 的结构化绑定或 `std::gcd`。

在不支持万能头文件的环境，按需包含标准头文件，例如 `iostream`、`vector`、`algorithm`、`queue`、`string`、`cstdio`；不要以删掉必要头文件来掩盖重名问题。[GCC 头文件说明](https://gcc.gnu.org/onlinedocs/libstdc++/manual/using_headers.html)、[stdc++.h 源码](https://gcc.gnu.org/onlinedocs/gcc-13.1.0/libstdc++/api/a00839_source.html)可用于核对其实现性质与包含范围。

## 二、两类冲突，处理方法不同

### 1. 全局变量与已有全局函数重名：声明就失败

```cpp
#include <bits/stdc++.h>
using namespace std;

int time = 0;  // 错误示例：已有全局 time 函数，不能再声明同名变量

int main() {
    return 0;
}
```

常见报错含 `redeclared as different kind of entity` 或 `redefinition ... different kind of symbol`。

| 避免用作全局变量的名字 | 已有含义 | 建议替代 |
| --- | --- | --- |
| `time`, `clock` | 时间函数 | `tim`, `tick` |
| `pow`, `sqrt`, `exp`, `log`, `log2` | 数学函数 | `power`, `rootVal`, `expVal`, `logVal`, `lg2` |
| `rand`, `srand` | 随机数相关函数 | `rnd`, `seedVal` |
| `y0`, `y1`, `yn`, `j0`, `j1`, `jn` | 部分平台暴露的贝塞尔函数 | `yStart`, `yEnd`, `rowIdx`, `colIdx` |
| `index`, `rindex`, `random` | 部分平台暴露的 C/POSIX 扩展函数 | `idx`, `ridx`, `rnd` |

**平台有差别**：扩展函数是否可见取决于系统 C 库、编译选项和头文件组合，不能以“Windows 上通过”推断 Linux 上也通过。相关函数可查 [GNU C 库函数索引](https://www.gnu.org/software/libc/manual/2.37/html_node/Function-Index.html)。`link` 通常由 `<unistd.h>` 声明，不能笼统说它一定由 `<bits/stdc++.h>` 引入；若实际包含了该声明，同名全局变量也会冲突。

**修复：改变量名，并同步修改引用。** 删除 `using namespace std;` 或把变量写成 `::time` 都不能修复声明阶段的冲突。

### 2. 全局变量与 std 中的名字重名：使用时歧义

```cpp
#include <bits/stdc++.h>
using namespace std;

int count = 0;  // 声明本身可以通过

int main() {
    count++;   // 错误示例：全局 count 与 std::count 产生歧义
    return 0;
}
```

常见报错含 `reference to 'count' is ambiguous`。即使你没有调用 `std::count`，裸写 `count` 仍可能歧义。

| 高危名字 | 建议替代 |
| --- | --- |
| `count`, `next`, `prev`, `distance` | `cnt`, `nxt`, `prv`, `dist` |
| `rank`, `hash`, `left`, `right` | `rk`, `hs`, `l`, `r` |
| `min`, `max`, `begin`, `end` | `mn`, `mx`, `bg`, `ed` |
| `find`, `sort`, `swap` | `pos`, `sortVal`, `tmp` |
| `map`, `set`, `queue`, `stack` | `mp`, `st`, `q`, `stk` |

**首选修复：改名。** 也可以移除 `using namespace std;`，对标准库名称写 `std::`；若确定是第二类冲突，`::count` 可以明确访问自己的全局变量，但不建议在考场大量加限定符补救。

### 3. 局部变量和成员变量：不是同名就一定 CE

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Point {
    int x, y1;             // 成员名可以使用 y1
};

int main() {
    int count = 0;         // 局部变量遮蔽外层名字，此处不会歧义
    ++count;
    int max = 10;          // 声明可以通过，但后面裸写 max(1, 2) 会失败
    cout << count << ' ' << max << ' ' << std::max(1, 2) << '\n';
    return 0;
}
```

该程序输出 `1 10 2`。**作用域决定查找结果**：不要把“高危全局变量名”理解成“任何位置都禁止使用”。局部同名可能遮蔽函数，仍建议保持 `cnt`、`mx` 等统一命名。

## 三、万能头文件不会替你消除的陷阱

| 陷阱 | 为什么出错 | 推荐写法 |
| --- | --- | --- |
| `#define int long long` | 宏替换影响后续声明、函数签名和内存占用；写在头文件前还会破坏库声明 | `using ll = long long;`，大整数单独用 `ll` |
| `#define min(a,b) ...`、`#define max(a,b) ...` | 宏不理解命名空间，连 `std::max(...)` 也可能被替换 | 使用标准库函数，不定义同名宏 |
| `max(1, 2LL)` | 两个实参推导出的模板类型不同 | `max(1LL, 2LL)` 或 `max<ll>(1, 2LL)` |
| `ll ans = a * b;`，其中 a、b 是 int | 先按 int 乘法计算，可能在赋值前溢出 | `ll ans = 1LL * a * b;` |
| 用 `pow(2, k)` 求整数幂 | 走浮点运算，转换回整数可能受精度影响 | 非负 k 且结果可表示时用 `1LL << k`，大幂用整数快速幂 |
| 换标准后同一名字报歧义 | 新标准可能引入新的库名称 | C++17 起特别留意 `size`、`data`、`gcd`、`visit` 等全局名字 |

`1LL << k` 也不是无限大整数：这里仅用于 `0 ≤ k ≤ 62`；仍须核对题目范围。

推荐常用变量：`n, m, k, cnt, tot, idx, tim, nxt, vis, dist, fa, dep, dfn, low, dp, ans, sum, sz, len, mn, mx`。这是一组实用命名习惯，不是对所有第三方库和未来版本的“永不冲突”保证。

## 四、编译报错速查

先读**第一条实际 error**，不要被后面的连锁报错带偏。

| 报错关键词 | 优先检查 | 操作 |
| --- | --- | --- |
| `bits/stdc++.h ... No such file` / `file not found` | 当前编译器与标准库是否支持该头文件 | 选用已安装的 GCC/libstdc++ 工具链，或按需包含标准头文件 |
| `redeclared ... different kind` | 全局变量是否与已声明函数重名 | 把 `time`、`y1`、`index` 等改名 |
| `reference ... ambiguous` | `using namespace std;` 下的裸名字是否重名 | 改成 `cnt`、`nxt`、`rk` 等；必要时加明确限定符 |
| `cannot be used as a function` | 局部变量是否遮蔽了函数 | 变量改名；调用标准库函数写 `std::max` 等 |
| `no matching function ... max/min` | 参数类型是否不同 | 显式统一类型，不靠换头文件解决 |

练习时可用以下命令检查本文 C++14 示例；正式提交应使用考场规定的命令与选项：

```bash
g++ -std=c++14 -O2 -Wall -Wextra main.cpp -o main
```

**考前速记：全局少用 `time/y1/index`，计数用 `cnt`、后继用 `nxt`、最值用 `mn/mx`；每题先编译、再跑样例、最后确认提交的是当前源文件。**

提交目录与读写要求见[防爆零与提交检查清单](防爆零与提交检查清单.md)，容器选择见[STL 容器的使用和选择](STL容器的使用和选择.md)。
