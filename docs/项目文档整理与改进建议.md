## 二、通用 vs MY 个人场景：内容分类定位（核心）

所有内容按「能否公开分发」和「是否含个人信息」分三类：

### A. 通用内容（可公开、可分享、长期维护）

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 历年初赛/复赛真题及答案（2013-2025） | `CSPJ/csp-j初赛真题/`、`CSPS/csp-s初赛真题/`、`CSPS/csp-复赛/` | 仓库主体，通用 |
| 知识点梳理 / 真题考点分析 / 答题技巧 | `CSPJ/csp-j复赛/`、`CSPS/csp-复赛/` 等 | 原创整理，通用价值最高 |
| 备考指南 / 3 天突击计划 | `CSPS/csp-s初赛真题/` | 通用方法论；其中的「目标 55 分」等个人定位见 §五-3 |
| NOI 官方大纲、NOI-Linux 指南 | `NOI/` | 官方资料，通用 |
| Hello 算法、答题卡说明 | `参考资料/` | 通用学习资料 |

### B. 第三方参考内容（纳入通用，明确标注来源，不移入个人区）

> 定位（已确认）：此类内容**仍属通用资料，保留在通用目录**，不做版权隔离；处理方式是**明确标注第三方来源**，在 README 索引中与原创整理区分开。

| 内容 | 位置 | 处理方式 |
| --- | --- | --- |
| 学而思课程大纲（J/S）与讲义 | `CSPJ/学而思课程/`、`CSPS/学而思课程/` | 保留原位；标注「第三方（学而思）课程资料，版权归原作者」 |
| 教培机构整理的真题解读 PDF | `CSPJ/csp-j初赛准备/` | 保留原位；标注「第三方整理资料，版权归原作者」 |
| Hello 算法、真题 PDF 等第三方资料 | `参考资料/`、各真题目录 | 同上，README 统一声明 |

### C. MY 个人场景（含个人信息/进度，默认不对外）

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 每日训练卷（按日期命名） | `MY/MY_CSP-S1_2026-08-23_*.pdf/.docx` | 个人备考进度产物 |
| 个人目标与分数定位 | 散落在各攻略文档中 | 应抽离集中（见 §五-3） |
| 个人环境配置 | git remote（`github-my` SSH 别名）、`.claude/settings.local.json` | 属机器本地配置，不入库 |

**一句话判据**：换一个考生拿到这份仓库是否依然完全适用？适用 → A / B（均为通用，B 仅额外标注第三方来源）；不适用（含"我的"进度、目标、环境）→ C 进 `MY/`。

## 五、改进建议（按优先级）

### 高优先级（建议尽快做）

1. **明确 MY 区边界**：新增 `MY/README.md`，写明「此目录为个人备考数据，含个人进度与目标，不属于通用资料」；今后所有个人产物（训练卷、个人计划执行记录、分数目标）只进 `MY/`，不再散落到通用目录。
2. **修正拼写错误**：目录 `csj-j初赛准备` → `csp-j初赛准备`；文档「复试」→「复赛」（用 `git mv` 保留历史，并同步修正 README 中的引用）。
3. **标注第三方来源**：学而思课程、教培解读 PDF 等 B 类资料**保留在通用目录不移入 MY**；在 README 目录索引中标注「第三方资料，版权归原作者」，并与原创整理内容区分展示。
4. **补齐真题缺口**：收集 2025 年 CSP-J1 初赛真题及答案，放入 `CSPJ/csp-j初赛真题/`。

### 中优先级（逐步做）

5. **生成产物不入库**：`.gitignore` 增加 `*-preview.pdf`、`.claude/`，并 `git rm --cached` 移除已跟踪的 preview 文件（本地保留）。
6. **多版本资料建索引**：在 `CSPS/csp-s初赛真题/` 增加 `readme.md`，说明 2025 年四个文件的关系（试题 / 答案 / 干净试卷版 md / docx）及推荐使用顺序。
7. **合并复赛重叠文档**：三篇复赛文档明确分工或合并为「真题分析（逐年）」+「知识体系（按专题）」两篇，消除重复。
8. **README 表格化索引**：为每个目录补一行「内容 / 更新至 / 优先级」，并在目录结构中登记 `MY/` 与 `docs/`。
9. **清理空目录**：`csp-j复赛真题/` 要么补充 2024-2025 J 组复赛真题，要么删除。

### 低优先级（持续优化）

10. **统一命名规范**：真题类 `YYYY_CSP-Xn_轮次_试题|答案.ext`（下划线分隔、无空格），攻略类保持现有中文命名；存量文件可渐进改名。
11. **清理残留 .DS_Store**（部分目录仍存在，虽已被忽略）。
12. **推送待推提交**：`git push` 同步 `a965c37`（远程 HTTPS 需钥匙串凭证，可按此前方式走 `github-my` SSH 别名）。

## 六、MY 个人场景的持续工作流建议

| 事项 | 建议做法 |
| --- | --- |
| 训练卷命名 | `MY/训练卷/YYYY-MM-DD_主题.pdf`，例：`2026-08-23_每日训练卷.pdf` |
| 进度追踪 | 新增 `MY/我的备考目标.md`：目标分数、省份晋级线、每日打卡、错题本入口 |
| 与通用文档的关系 | 通用攻略只写方法论；个人目标/进度一律引用 MY 区文件，避免「55 分」这类个人化数字散落在通用文档里 |
| 同步策略 | 通用内容 → 公开仓正常提交推送；MY 内容 → 若仓库公开，考虑将 `MY/` 加入 `.gitignore` 或改放私有仓 |
